Open questions

Blocking items first — these need a human answer before the mapping can be trusted end-to-end. Non-blocking items are safe to proceed on with the stated assumption.

BlockingFooter business info data source

Kitchen hours, address, delivery phone, email, and social links (nodes 6:151–6:169, 6:144) are plain static text/vectors in Figma with no CMS/config binding shown — exactly the content this story is about, so how it's sourced changes the component design.

arc assumption: modeled all footer business-info components as prop-driven and hardcoded the copy 1:1 from the frame (static-props), not a CMS-backed data model.
static-props — Static props/constants; footer copy ships hardcoded in code, matching the Figma text exactly. (assumed)
cms-driven — CMS/admin-configurable; hours, address, contact info and social links are fetched from a backend so staff can edit them without a deploy.
Non-blockingIcon implementation source

All icons (fire-extinguisher, truck, star, shield, compass, plus, arrow-right, shopping-cart, instagram, facebook, twitter) are raw Figma vector paths whose layer names match an existing open-source icon set (Lucide) exactly.

arc assumption: implement via the shared Icon component backed by Lucide (name-matched), rather than hand-tracing each vector's path data.
Non-blockingFooter legal link destinations

"Privacy Policy" and "Delivery Terms" (6:174, 6:175) are styled as links with no destination page/URL defined.

arc assumption: render as anchors with placeholder href="#" until real destination pages exist.
Non-blockingSocial icon link destinations

Instagram/Facebook/Twitter icon buttons (6:145, 6:147, 6:149) have no attached profile URLs in the Figma file.

arc assumption: modeled href as a required prop on SocialIconButton, defaulted to placeholder # until real URLs are supplied.
Non-blockingFooter responsive / mobile layout

The frame is a single fixed 1440px desktop composition; no tablet/mobile variant of the 3-column footer is provided.

arc assumption: the 3 footer columns stack vertically below a standard tablet breakpoint; the bottom bar's copyright/legal-links row stacks to two centered lines on narrow viewports.
Non-blockingHover / focus states not drawn

Footer links, social icons, and nav items only show one static visual state in the frame; no hover/focus/pressed state is drawn anywhere.

arc assumption: conventional web affordances — opacity/underline shift on hover, visible focus ring for keyboard nav — consistent with the page's minimal styling.
